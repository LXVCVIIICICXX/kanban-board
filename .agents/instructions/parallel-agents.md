# Регламент параллельной работы агентов

Этот документ описывает, как два независимых AI-агента (например, Gemini в Antigravity IDE и Claude в Claude Code CLI) могут параллельно работать в одном репозитории, не конфликтуя за файлы и сетевые порты.

---

## 1. Концепция изолированных рабочих директорий (Git Worktree)

Если оба агента работают одновременно в одном репозитории, переключение веток в одной папке будет сбрасывать изменения другого агента и перезапускать dev-серверы. 
Для полной изоляции используется механизм **`git worktree`**.

* **Основная папка:** `<project_dir>` — закреплена за основным агентом (например, Gemini).
* **Параллельная папка:** `<project_dir_agent2>` — создается для второго агента (например, Claude).

### Как развернуть окружение для параллельного агента:
В терминале выполняется команда из корня основного репозитория:
```bash
git worktree add ../project_claude -b feature/claude-task-name
```
Это создаст папку `project_claude` на отдельной ветке `feature/claude-task-name`. Второй агент будет работать исключительно в этой изолированной папке.

### Удаление рабочей копии после завершения задачи:
После завершения работы, коммита и слияния ветки, папка удаляется:
```bash
git worktree remove ../project_claude
```

---

## 2. Разделение сетевых портов

Каждый агент должен запускать свои dev-серверы на собственных портах, чтобы они не конфликтовали.

| Агент | Папка | Порты |
| :--- | :--- | :--- |
| **Основной агент** | `/project` | Порт трекера + порты приложений (например, 5000, 5001, 8000) |
| **Второй агент** | `/project_agent2` | Смещенные порты (например, 5002, 8001) |

---

## 3. Разделение и зависимости задач на Kanban-доске

1. Перед тем как начать разработку, агент проверяет Kanban-доску в папке `tracker` (или читает файлы в `.agents/tasks/To do/` и `Backlog/`).
2. Агент выбирает задачу, где:
   * Он указан в поле `assignee`.
   * В поле `dependencies` все указанные ID задач находятся в папке `Done`.
3. Агент переносит выбранный файл задачи из `Backlog` в папку `To do` (устанавливая статус «В работе»).
4. Ни в коем случае нельзя брать задачи другого исполнителя или задачи, находящиеся в блоке (`Blocked`).
