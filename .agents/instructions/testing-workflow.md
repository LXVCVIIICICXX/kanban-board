# Регламент тестирования и верификации

Этот документ определяет процессы тестирования, использования баз данных при тестировании и ведения лога обучения.

---

## 1. Изолированные базы данных для тестирования
Чтобы не загрязнять основную базу данных мусорными записями во время разработки:
1. **Основная БД:** Используется в корне основного проекта. Содержит стабильные данные и мейн-прогресс.
2. **Тестовые БД:** Каждый агент в своей изолированной папке (worktree) использует собственный файл БД (например, `test_project.db`).
3. **Инициализация:** При первом запуске в тестовом окружении автоматически запускаются миграции/сидинг для наполнения базы начальными тестовыми данными.

---

## 2. Автотестирование
Мы придерживаемся концепции автоматизированного тестирования для ключевых механик проекта:
1. **Написание тестов:** При создании новой логики пишется соответствующий тест.
2. **Запуск тестов:** Агент обязан запустить тесты перед сборкой и слиянием ветки.
3. **Сдача задачи:** Ручная верификация UI пользователем является финальным этапом приемки. Если пользователь нашел баг — агент фиксирует его и вносит исправление в логику и тесты.

---

## 3. Обучение и фиксация опыта (Learning Log)
Для непрерывного улучшения качества работы агентов в корне проекта ведется файл **`learning_log.md`**.

В него записывается:
* Какая задача была выполнена (ID и название).
* Какие тесты были написаны и сработали хорошо.
* Была ли задача принята пользователем с первого раза (или какие правки потребовались).
* Выводы и паттерны, которые помогли решить задачу быстрее и безбажнее.

Каждый агент перед началом работы обязан ознакомиться с последними записями в `learning_log.md`, чтобы не повторять прошлых ошибок.
