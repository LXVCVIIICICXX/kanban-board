# Регламент Code Style и Дизайн-Системы

Этот документ определяет правила написания кода и использования стилей для всех агентов в проекте.

---

## 1. Стилизация и Дизайн-Система (CSS Tokens)

Все стили UI должны опираться на глобальные CSS-переменные или согласованную дизайн-систему проекта. Запрещается хардкодить цвета и шрифты в CSS-файлах компонентов.

### Глобальные CSS переменные:
* **Цвета фона и поверхностей:**
  * `--color-bg-deep`: глубокий темный фон
  * `--color-bg-card`: цвет панелей и карточек
  * `--color-border`: основной цвет рамок
* **Акцентные цвета:**
  * `--color-primary`: основной цвет бренда/акцентов
  * `--color-secondary`: вторичный цвет
  * `--color-success`: цвет успеха/готовности
  * `--color-danger`: цвет ошибок/блокировок
* **Шрифты:**
  * `--font-sans`: основной шрифт для текстов, настроек, списков
  * `--font-mono`: шрифт для кода, идентификаторов, логов

---

## 2. Разработка кода

* **Типизация:** Все структуры данных должны быть строго описаны. Использование типа `any` или нетипизированного кода не рекомендуется.
* **Линтеры:** Проверка кода выполняется с помощью установленного линтера (например, `eslint` для JS/TS, `flake8` или `pylint` для Python). Перед коммитом код должен быть отформатирован.
* **Качество кода:** Код должен быть модульным, с понятными именами переменных и функций на английском языке. Логически сложные функции необходимо снабжать комментариями.
