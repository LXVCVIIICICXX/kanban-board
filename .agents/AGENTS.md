# Регламент разработки проекта и работы с задачами

Этот документ определяет правила совместной работы человека и AI-агентов (Gemini, Claude) над проектом с использованием Kanban-доски.

---

## 1. Язык общения и кодирования
* **Диалоги, объяснения, комментарии в коде, логи коммитов и тексты интерфейса (UI) — на русском языке.**
* **Сам код (переменные, функции, классы), технические термины и названия Git-веток — на английском языке.**

---

## 2. Разделение ролей агентов
Проект использует автоматическое или ручное распределение задач между исполнителями:
* **Gemini (Antigravity IDE)**: специализируется на системной архитектуре, бэкенде, базах данных и интеграциях.
* **Claude (Claude Code CLI)**: специализируется на фронтенде, пользовательских интерфейсах, стилях (CSS/HTML) и визуальных эффектах.
* **Human**: ручное тестирование, дизайн-решения, финальная приемка.

---

## 3. Трекинг задач (Kanban & Metadata)

Все задачи хранятся в виде `.md`-файлов в директории `.agents/tasks/{Backlog, To do, Done}/*.md`.
Они отображаются на локальной Kanban-доске (сервер запускается в папке `tracker` через `node server.cjs`).

Доска **обновляется вживую**: сервер по SSE (`/api/events`) + `fs.watch` следит за `.agents/tasks/*` и присылает браузеру сигнал при любом перемещении/правке задачи — ручное обновление страницы не требуется.

> [!IMPORTANT]
> **Единый источник состояния доски — `main`.** При параллельной работе у каждого агента своя копия `.agents/tasks/`. Чтобы доска показывала актуальную картину, **перемещения задач между папками `Backlog/To do/Done` нужно оперативно коммитить и отправлять в общий репозиторий (ветку `main`)**.

### Метаданные задач
Каждая задача содержит комментарии-метаданные в самом верху файла:
* `<!-- id: <8-значный хэш> -->` — уникальный ID задачи.
* `<!-- assignee: <Gemini / Claude / Human / Both> -->` — исполнитель.
* `<!-- dependencies: <id1>, <id2> -->` — зависимости от других задач по их ID.

> [!IMPORTANT]
> **Блокировка задач:** Если задача B зависит от задачи A, и задача A еще не перенесена в папку `Done`, то задача B считается **заблокированной** (`Blocked`). Агенты не должны брать в работу заблокированные задачи!

---

## 4. Параллельная работа и Git-Workflow

Чтобы агенты не мешали друг другу и не перезаписывали рабочий каталог:
1. **Отдельные ветки:** Каждый агент работает строго в своей ветке:
   * Gemini: `feature/gemini-<task-name>` или `fix/gemini-<task-name>`
   * Claude: `feature/claude-<task-name>` или `fix/claude-<task-name>`
2. **Изоляция каталогов (Git Worktree):** При необходимости параллельной работы используется механизм `git worktree` для развертывания ветки в соседней папке (например, `../project_claude`).
3. **Правила слияния (Merge):**
   * Перед слиянием ветки в `main` агент обязан запустить сборку и тесты для проверки типов.
   * Слияние производится только через команду `/git-merge` после подтверждения пользователя.
   * После слияния файл задачи перемещается в папку `Done`, а ветка удаляется.
