# /git-merge — слияние рабочей ветки в main

Эта команда автоматизирует процесс слияния текущей ветки задачи в ветку `main` после успешного завершения работы и ручной проверки UI.

## Алгоритм работы

1. **Проверка текущей ветки**:
   - Запустить `git branch --show-current`, чтобы определить имя текущей ветки.
   - Если текущая ветка — `main`, сообщить пользователю, что мы уже на `main` и сливать нечего.
   - Убедиться, что имя ветки соответствует паттерну `feature/*`, `fix/*` или `chore/*`.

2. **Проверка статуса рабочей директории**:
   - Выполнить `git status --short`.
   - Если есть незакоммиченные изменения в коде, предложить закоммитить их перед слиянием.

3. **Слияние**:
   - Переключиться на `main`:
     ```bash
     git checkout main
     ```
   - Подтянуть последние изменения:
     ```bash
     git pull origin main
     ```
   - Слить рабочую ветку без перемотки (no-fast-forward), чтобы сохранить историю коммитов задачи:
     ```bash
     git merge --no-ff <имя-рабочей-ветки> -m "Merge branch '<имя-рабочей-ветки>'"
     ```
   - Если возникли конфликты, остановить выполнение команды и попросить пользователя разрешить их вручную (не пытаться разрешать конфликты самостоятельно).

4. **Уборка**:
   - Удалить локальную рабочую ветку:
     ```bash
     git branch -d <имя-рабочей-ветки>
     ```

5. **Отчет**:
   - Вывести краткий статус слияния пользователю.
